# Auditor database schema

`schema.prisma` models the 16 tables in the new auditor ER diagram. This service
currently owns the whole schema so PostgreSQL can enforce the diagram's foreign
keys across users, billing, audits, and knowledge-base records.

## Apply the migrations

Start PostgreSQL from the repository root:

```powershell
docker compose up -d postgres
cd services/subscription-service
npx prisma migrate deploy --config prisma7.config.ts
npx prisma generate --config prisma7.config.ts
```

The config currently reads `DATABASE_URL` from the service's `.env` (or the process
environment), not the repository root `.env`. Verify the connection points to the
intended database. For a local process using the Docker Compose PostgreSQL server,
the host and port are `127.0.0.1:5433`.

Keep the original migration and `migration_lock.toml`. A fresh database applies
both migrations in order. An existing database with the original migration applied
uses the new replacement migration. It removes seven obsolete tables and replaces
columns in `plans`, `subscriptions`, and `payments`.

The replacement migration runs in a transaction and refuses to proceed if any of
the ten legacy tables contain rows. It does not backfill existing data. If data
must be retained, prepare a separate data migration before applying it.

If tables were manually dropped, migration history may disagree with the database.
For a disposable development database only, rebuild it with:

```powershell
npx prisma migrate reset --config prisma7.config.ts
npx prisma generate --config prisma7.config.ts
```

**Reset deletes all data in the configured database schema.** Do not use it on a
database whose data must be retained.

The migration enables PostgreSQL's `citext` extension before creating `users.email`.
The migration connection needs permission to create that extension.

## Modeling assumptions

- A user has zero or one current subscription (`subscriptions.user_id` is unique).
- Consent uses the composite primary key `(user_id, doc_type, doc_version)`.
- Diagram types map to native PostgreSQL UUID, CITEXT, BYTEA, TIMESTAMPTZ, JSONB,
  SMALLINT, BIGINT, NUMERIC, and TEXT[].
- The diagram does not specify nullability. Soft-delete and revocation timestamps,
  Stripe plan/customer/subscription IDs, subscription period end, audit chain/fork
  values, report PDF URI, and triage score/decision are nullable for pending work
  or free plans. Other scalar fields are required.
- UUIDs are generated by Prisma; security-event IDs use a database sequence.
  Consent acceptance and security-event timestamps default to the current time.
- Required foreign keys restrict parent deletion. Use the diagram's soft-delete
  fields where available; no cascading data deletion is configured.
- Status, role, stage, and similar fields remain strings because the diagram does
  not define their allowed values.

These files create database structure; they do not add service APIs or seed data.
